## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client form → createAndSendOffer ('use server') | Untrusted form input crosses into a privileged server action |
| server action → staff_app_create_offer (RPC) | Write goes through the org-writer-gated definer function |
| server action → Ferozo SMTP | Offer email + link leave the app |
| emailed link → /o/[token] | Public link target (built in Phase 4; 404 until then) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-09 | Elevation | non-member invoking createAndSendOffer directly | mitigate | Action re-checks `staff_app_my_membership` and throws before any RPC/email (copied cv-actions gate); the RPC independently gates `is_org_writer` |
| T-3-10 | Info disclosure | service-role misuse in the send path | mitigate | Action uses ONLY the authenticated client; service-role client is never imported here (grep-enforced); RPC needs no service-role |
| T-3-07 | Repudiation | silent success when SMTP fails | mitigate | UI checks `mail.ok`; failed send shows honest state + wa.me fallback (D-02); verified in checkpoint step 5 |
| T-3-11 | Info disclosure | raw token logged / persisted app-side | mitigate | Token only used to build the link in memory; never logged; only its hash persists (03-01) |
| T-3-12 | Tampering | double-tap creating duplicate offers/gigs | mitigate | Submit disabled in flight; re-send reuses the same in-memory link (no second RPC) — Pitfall 5/7 |
