<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → CV object | CVs are PII (Ley 25.326); the private bucket must not be publicly reachable |
| server action → service-role | Signing needs elevated perms that must never reach the client |
| app → Google Drive | Drive CVs open in the user's own Google session |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-14 | Information Disclosure | public/guessable CV URL (habeas data) | mitigate | Private `staff-cvs` bucket + short-TTL (60s) signed URL minted server-side only; no public URL rendered; Drive links open in the user's own session, not proxied. |
| T-02-15 | Information Disclosure | service-role key exposure via CV signing | mitigate | Signing is a `"use server"` action using `admin.ts` (server-only `SUPABASE_SERVICE_ROLE_KEY`); the client receives only the time-limited URL; grep-asserted no client import of the key. |
| T-02-16 | Elevation of Privilege | non-member signing a CV | mitigate | `signCv` checks `staff_app_my_membership` and throws 'forbidden' before signing; a non-member cannot obtain a URL even by calling the action. |
| T-02-17 | Information Disclosure | profile PII reachable by non-members | mitigate | Profile row fetched via the `security_invoker` `staff_app_profiles` view → RLS returns 0 rows for non-members (proven in Task 1). |
| T-02-SC | Tampering | no new package installs this plan | accept | Uses only libs from 02-02 (lucide, supabase-js); no new supply-chain surface. |
</threat_model>
