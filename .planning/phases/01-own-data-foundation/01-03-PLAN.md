<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public web (anon key in form) → app DB | The published anon key can write applicant rows and upload CVs; must be tightly constrained |
| HITO project → app project | One-time read-only pull; the app must never write to HITO |
| CV objects | Applicant CVs are PII; the bucket must never be publicly readable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-09 | Tampering / DoS | anon INSERT on staff_profiles | mitigate | Tight `WITH CHECK` (required fields + org IS NULL), column-level GRANT on only form columns, existing form honeypot; bucket private (Task 1) |
| T-01-10 | Elevation of Privilege | anon setting privileged columns | mitigate | BEFORE INSERT trigger owns organization_id/estado; anon has no INSERT grant on organization_id/rating/notas_internas (asserted via has_column_privilege) |
| T-01-11 | Information Disclosure | CV objects / applicant PII | mitigate | `staff-cvs` bucket private; anon upload-only, no read; CVs served via signed URL later (Phase 2) |
| T-01-12 | Repudiation / data loss | cutover delta window | mitigate | Cutover BEFORE backfill freezes HITO; Vercel atomic deploy; Task 3 sweep imports the exact frozen 7 (pitfall #5) |
| T-01-13 | Info Disclosure / integrity | HITO read-only source | mitigate | Source A pull is SELECT-only on HITO; no writes/functions created there (D-02) |
| T-01-SC | Tampering | package installs | accept | No package installs; the CV-copy one-time script uses Node/curl built-ins against Supabase Storage REST |
</threat_model>
