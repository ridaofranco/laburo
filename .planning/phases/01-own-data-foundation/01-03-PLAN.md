## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public web (anon key in form) → staff_app | The published anon key can only create applicant rows through the validated public RPC; it cannot write staff_app tables directly |
| HITO public.staff_profiles → staff_app | One-time same-project read-copy; the app must never write to HITO's public.* tables |
| CV objects | Applicant CVs are PII in the existing private staff-cvs bucket; unchanged, never publicly readable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-09 | Tampering / DoS | anon intake path | mitigate | anon writes only via `public.staff_app_register_applicant`, which validates required fields and forces privileged columns; no direct anon INSERT on staff_app.staff_profiles; existing form honeypot retained |
| T-01-10 | Elevation of Privilege | anon setting privileged columns | mitigate | The register function owns organization_id/estado/source and ignores caller-supplied privileged columns; anon has no direct table INSERT (asserted via has_table_privilege) |
| T-01-11 | Information Disclosure | CV objects / applicant PII | mitigate | `staff-cvs` bucket unchanged (already private); anon upload-only, no read; CVs served via signed URL later (Phase 2) |
| T-01-12 | Repudiation / data loss | cutover delta window | mitigate | Cutover BEFORE backfill freezes HITO's public.staff_profiles; Vercel atomic deploy; Task 3 captures N at cutover and imports exactly N (pitfall #5) |
| T-01-13 | Info Disclosure / integrity | HITO public.* source | mitigate | Source A is a same-project SELECT/read of public.staff_profiles; writes go only to staff_app; no writes/functions created in public that mutate HITO data (D-02/D-03) |
| T-01-SC | Tampering | package installs | accept | No package installs; backfill is pure SQL via MCP (same-project INSERT...SELECT — no cross-project CV script needed) |
